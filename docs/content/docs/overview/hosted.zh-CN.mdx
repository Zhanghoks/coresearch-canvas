# 托管部署

生产有两个公网入口。浏览器只打开网页和 `agent-api`，不直连 Pi。

| 域名 | 落点 |
| --- | --- |
| `coresearch.xxx.com` | Vercel 上的 `web/` |
| `api.coresearch.xxx.com` | Cloudflare Tunnel → 服务器 `127.0.0.1:4100` |

服务器上用 [`deploy/production/docker-compose.yml`](https://github.com/Zhanghoks/Research-canvas/blob/main/deploy/production/docker-compose.yml) 跑：

- `agent-api`：校验 Supabase JWT，跑 Pi，写 Postgres。只监听回环 4100。
- `cloudflared`：Tunnel，把 `api.coresearch.xxx.com` 接到回环 4100。
- `app`（可选，默认关闭）：备用静态前端，只监听回环 3000。主站不要指到这个容器。用 `COMPOSE_PROFILES=app` 启用。

<Callout type="info">
本页描述的是**手工**部署流程，适合首次搭建和排查。日常部署已经自动化：push 到 `main` 之后 Vercel 部署前端、GitHub Actions 部署后端，不需要 SSH。完整的自动化流程、GitHub Secrets 配置、回滚方法见 [`deploy/production/README.md`](https://github.com/Zhanghoks/Research-canvas/blob/main/deploy/production/README.md)。
</Callout>

Pi 会话、进行中的工具确认和 SSE 都在这一个 `agent-api` 进程里。只跑一个副本。横向扩容前不要起第二个。

登录、Project、Conversation 和 Agent 事件在 Supabase。画布项目库和生成记录仍在浏览器本地，这不是整站云同步。

把下面的 `coresearch.xxx.com` 换成你的域名。建议一台装有 Docker Compose v2 的 Linux 服务器，内存留给 Pi 会话和 `pi-agent-data` 卷。

## 1. Supabase

在 SQL Editor 按文件名顺序执行 `agent-api/supabase/migrations/` 下的 `001` 到 `008`。已经执行过的不要重复跑。

Authentication → URL Configuration：

- Site URL：`https://coresearch.xxx.com`
- Redirect URLs：生产域；需要登录的 Vercel Preview 域；备用前端域（如果启用）

从 Dashboard → API 记下三项，只把 Secret Key 放在服务器上：

- Project URL
- Publishable key
- Secret key（`service_role`，不要以 `VITE_` 开头，不要放进 Vercel）

## 2. 服务器上的 Agent API

安装 Docker 与 Compose 插件后克隆仓库：

```bash
git clone git@github.com:Zhanghoks/Research-canvas.git
cd Research-canvas
cp agent-api/.env.production.example agent-api/.env
```

编辑 `agent-api/.env`：

| 变量 | 值 |
| --- | --- |
| `SUPABASE_URL` | Project URL |
| `SUPABASE_PUBLISHABLE_KEY` | Publishable key |
| `SUPABASE_SECRET_KEY` | Secret key |
| `AGENT_API_ORIGINS` | `https://coresearch.xxx.com`。多个来源用逗号分隔，不要空格，不要带路径或结尾斜杠 |
| `PI_PROVIDER` / `PI_MODEL` | 平台模型 |
| `PI_API_KEY` | 平台模型钥匙。只放在这里 |
| `PI_AGENT_DIR` | `/var/lib/research-canvas/pi` |
| `PORT` | `4100` |

完整变量清单（含每个变量缺失/错误时的现象）以 [`deploy/ENV.md`](https://github.com/Zhanghoks/Research-canvas/blob/main/deploy/ENV.md) 为准，这里只列最少够跑通这一步的几个。

不要设置 `AGENT_RUNTIME`。默认就是 Pi。

把这些值写进 `/srv/coresearch/env/production.env`（`chmod 600`），模板见 [`deploy/production/production.env.example`](https://github.com/Zhanghoks/Research-canvas/blob/main/deploy/production/production.env.example)。生产密钥只存在于这个文件里：不进 Git、不进镜像、不进 compose、不进 GitHub Secrets。

然后启动：

```bash
IMAGE_TAG=main /srv/coresearch/app/deploy.sh
```

`deploy.sh` 只做 `docker compose pull` + `up -d` + `/health` 轮询，**不在生产机上构建镜像**。镜像由 GitHub Actions 推到 GHCR。

要同时启用备用前端容器（默认关闭）：

```bash
export SUPABASE_URL=https://your-project.supabase.co
export SUPABASE_PUBLISHABLE_KEY=your-publishable-key
export AGENT_API_URL=https://api.coresearch.xxx.com
COMPOSE_PROFILES=app IMAGE_TAG=main /srv/coresearch/app/deploy.sh
```

`AGENT_API_URL` 必须是公网 API 地址。浏览器在用户机器上执行，填 `localhost` 会连到用户自己的电脑。

确认本机健康检查，并确认公网端口没有打开：

```bash
curl -sS http://127.0.0.1:4100/health
```

应返回 `{"ok":true}`。防火墙不要放行 4100 和 3000。

## 3. Cloudflare Tunnel

域名的 DNS 放在 Cloudflare。在服务器安装 `cloudflared`（[官方安装说明](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)），然后创建 Tunnel：

```bash
cloudflared tunnel login
cloudflared tunnel create coresearch
cloudflared tunnel route dns coresearch api.coresearch.xxx.com
```

`tunnel create` 会打印 Tunnel ID，并在 `~/.cloudflared/<TUNNEL_ID>.json` 写入凭据。把凭据和仓库里的 [`deploy/cloudflared/config.yml`](https://github.com/Zhanghoks/Research-canvas/blob/main/deploy/cloudflared/config.yml) 装到系统目录：

```bash
sudo mkdir -p /etc/cloudflared
sudo cp ~/.cloudflared/<TUNNEL_ID>.json /etc/cloudflared/<TUNNEL_ID>.json
sudo cp deploy/cloudflared/config.yml /etc/cloudflared/config.yml
```

编辑 `/etc/cloudflared/config.yml`：把 `<TUNNEL_ID>` 换成上一步的 ID，把域名换成你的域名。API 这一条保持：

```yaml
ingress:
  - hostname: api.coresearch.xxx.com
    service: http://127.0.0.1:4100
  - service: http_status:404
```

备用前端要对公网开放时，再加一条单独子域，指向 `http://127.0.0.1:3000`，并执行 `cloudflared tunnel route dns coresearch app-internal.coresearch.xxx.com`。不要把 `coresearch.xxx.com` 写进 Tunnel，那条域名留给 Vercel。

安装并启动服务：

```bash
sudo cloudflared --config /etc/cloudflared/config.yml service install
sudo systemctl enable --now cloudflared
```

从服务器外面检查：

```bash
curl -sS https://api.coresearch.xxx.com/health
```

同样应返回 `{"ok":true}`。用服务器公网 IP 访问 4100 应失败。

## 4. Vercel

在 Vercel 导入本仓库。根目录 [`vercel.json`](https://github.com/Zhanghoks/Research-canvas/blob/main/vercel.json) 会构建 `web/`。Production 环境变量与 [`deploy/vercel.env.example`](https://github.com/Zhanghoks/Research-canvas/blob/main/deploy/vercel.env.example) 相同：

| 变量 | 值 |
| --- | --- |
| `VITE_SUPABASE_URL` | Project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Publishable key |
| `VITE_AGENT_API_URL` | `https://api.coresearch.xxx.com` |

完整变量清单见 [`deploy/ENV.md`](https://github.com/Zhanghoks/Research-canvas/blob/main/deploy/ENV.md)。

不要在 Vercel 配置 `SUPABASE_SECRET_KEY` 或 `PI_API_KEY`。改环境变量后重新部署，这三个值在构建时写入前端。

把 `coresearch.xxx.com` 加为 Vercel 域名，并在 Cloudflare DNS 按 Vercel 给出的记录做 CNAME。

Preview 部署也要登录时，把该 Preview 来源追加到服务器的 `AGENT_API_ORIGINS`，重启 `agent-api`，并加入 Supabase Redirect URLs。来源必须和浏览器地址栏完全一致。

## 5. 邀请码

在能读到 `agent-api/.env` 的机器上：

```bash
cd agent-api
npm ci
npm run invite:create
```

产品界面不要展示内置 `test` 账号。该账号只给协议验收用。

## 6. 验收

```bash
cd agent-api
RUN_SUPABASE_RLS_TESTS=1 npm test
AGENT_API_URL=https://api.coresearch.xxx.com npm run acceptance:live
```

浏览器里再确认：

- 未登录只能看到邀请码门禁，进不了首页、画布和 Agent。
- 登录后 Agent 不要求用户填写模型 Key。
- 网络请求里没有 `PI_API_KEY`。SSE 使用 `Authorization` 头，JWT 不出现在 URL 里。

## 升级与备份

日常升级不需要手工操作：push 到 `main` 之后，GitHub Actions 会跑 typecheck 和 test、构建镜像推到 GHCR、SSH 触发服务器上的 `deploy.sh`，最后校验 `/health` 返回的 `version` 是否就是本次 commit。

需要手工升级或回滚时：

```bash
IMAGE_TAG=sha-<commit> /srv/coresearch/app/deploy.sh
```

升级会断开正在进行的 SSE，**并且会中断正在跑的 Agent run**。agent-api 启动时会 reconcile：把残留在 `status='running'` 的 run 标记为 `failed` 并补发 `run.failed` 事件，前端能正常收尾，但那一轮对话内容会丢失。

Postgres 用 Supabase 自己的备份。Pi 会话文件在 bind mount `/srv/coresearch/data/pi` 里，直接在宿主机上打包即可：

```bash
sudo tar czf /srv/coresearch/logs/data-$(date +%F).tar.gz -C /srv/coresearch data
```

Secret key 和 `PI_API_KEY` 不要写入集中日志。
